# mini-CogSim —— 在本机复刻 LLNL 的「认知仿真」（CogSim）架构

> **Research prototype and scope notice:** mini-CogSim is an independent, reduced-order research prototype. It is not an LLNL product and is not affiliated with or endorsed by LLNL, NIF, or the cited authors. The included simulator and example “experiment” data are synthetic; this repository does not contain HYDRA, LLNL internal software, or NIF experimental data. Numerical results in this repository are demonstrations of the prototype workflow, not validated predictions for a real fusion target or engineering design.
> 目标：把 LLNL 用来预测 NIF 靶丸内爆、并在 2022-12-05 点火前给出
> **P(点火) > 70%** 的那套方法，等比缩小到一台普通工作站上跑通。
> 保留**全部结构性要素**，只把"超算规模"降下来。

## 一、LLNL 的 CogSim 到底是什么

不是"一个 AI 模型"，而是**一条把超算仿真和真实实验缝在一起的流水线**。

| 环节 | LLNL 用的东西 | 干什么 |
|---|---|---|
| 大规模仿真 | HYDRA（辐射流体程序）+ HyPyD（自动配置/批量提交）+ **Merlin**（工作流编排） | 在 Sierra / Lassen 上跑了 **1.5×10⁵ ~ 10⁸** 次内爆仿真，自建"大数据" |
| 多模态代理 | MaCC 自编码代理 / LBANN | 用深度网络模仿 HYDRA，**快几个数量级** |
| 仿真→实验校正 | **迁移学习**（Transfer Learning） | 冻结大部分层，用几十发真实实验重训末层，学的就是"仿真与实验的差值" |
| 不确定度 | 深度集成 + 贝叶斯标定 + 蒙特卡洛传播 | 输出的是**分布**，不是一个数 |
| 决策 | 点火概率、稳健性设计指标 | 回答"这一发该不该打" |

### 三个关键论文

1. **Anirudh, Thiagarajan, Bremer & Spears (LLNL), arXiv:1912.08113**
   *MaCC：流形一致 + 循环一致的 ICF 代理*
   → 本项目的 `cogsim/models/macc.py`
2. **Humbird, Peterson, Salmonson & Spears, Phys. Plasmas 28, 042709 (2021)**
   *认知仿真模型：把仿真和实验数据合进一个模型*
   → 本项目的 `cogsim/models/transfer.py`
   *实测：用 20 发实验重训后，log 产额误差 73%→3%，离子温度 200%→7%，bang time 9%→4%*
3. **Spears et al., Science 389, 727 (2025)**
   *物理信息深度学习预测 NIF 点火*
   → 本项目的 `cogsim/bayes.py`
   *2022-12-05 打靶前给出 74% 点火概率，实测落在预测区间内；
   用 57 次新仿真做迁移学习就完成了对新设计的适配*

### 为什么必须这么做

* 仿真**便宜但系统性不准**（辐射流体程序必须做简化假设：对称性、降阶模型、网格分辨率）；
* 实验**准但极贵**（NIF 一年只有十几次点火尝试）；
* 单独用哪个都不行 → 用 ML 把两者缝起来，并且**把不确定度说清楚**。

## 四、各环节的"原理"与本项目怎么落地

### S1 仿真数据库 —— 自建大数据

* **原理**：高保真程序单次太贵，无法直接做 UQ/反演。先拿它**批量产数据**，
  把"求解器"变成一个"数据集"，再用便宜的代理去学。
* **落地**：`simulator.py` 是一条有物理结构的半解析链条
  （黑腔能量平衡 → 烧蚀压标度 → 火箭模型 → 压缩标度 → 燃烧份额 → α 加热放大 → 点火悬崖），
  常数按 NIF 标称工况标定：标称点落在 **v_imp≈400 km/s、ρR≈1.1 g/cm²、Y≈2 MJ** 的真实量级上。
  输出**多模态**：6 个标量 + 4 张 32×32 成像（3 个视角的中子成像 + 1 张 X 射线自发射）。
* **换真家伙**：把 `workflow._run_one` 里的 `simulate(...)` 换成
  `subprocess.run(["hydra", ...])` / PLUTO / FLASH 的命令行调用，上层代码一行都不用改。

### S2 代理模型 —— 流形一致 + 循环一致（MaCC）

* **原理**：不是简单的"输入→输出回归"。四个网络互连：
  * `E/D`：自编码器，捕捉多模态观测之间的**物理流形**（哪些观测组合是物理上可能的）；
  * `F`：前向代理 `x → z`；
  * `I`：逆向模型 `z → x`。
  * 损失 = 重建 + **流形一致** `‖F(x) − E(o)‖²` + **循环一致** `‖I(F(x)) − x‖²`。
  * 好处：预测永远物理合法、小样本更鲁棒、顺带白送一个可微逆向模型。
* **落地**：`models/macc.py`，两阶段训练（先训 E/D 定义流形，再联合训 F/I）。

### S3 迁移学习 —— 补上"仿真-实验鸿沟"

* **原理**：仿真误差是**系统性的**，不是噪声，堆再多仿真数据也消不掉。
  做法是先在仿真上学物理骨架，**冻结自编码器**（流形不能被几十发数据动摇），
  只用实验重训前向网络末几层，配合 **L2-SP 正则**防止过拟合。
* **落地**：`models/transfer.py`。本项目里"实验"= 真值 + 一个系统偏差 + 测量噪声，
  偏差项刻意做成随靶丸粗糙度变化（真实 ICF 里这正是最难修的部分）。
  *细节*：按各观测量测量噪声做**逆方差加权**，否则噪声大的量（burn width）会把网络带偏。

### S4 贝叶斯标定 + 不确定度传播 —— 从"预测数值"到"预测概率"

* **原理**（Science 2025 的核心）：不回答"产额是多少"，回答**"点火概率是多少"**。
  三类不确定度分开处理：
  1. **打靶涨落**（aleatoric）：激光能量精度、靶丸缺陷、驱动不对称……用涨落向量 δ 的分布描述；
  2. **认知不确定度**（epistemic）：代理没学准 → **深度集成**的成员离散度；
  3. **残余系统偏差**：迁移后仍有的偏差 → 一个待推断的偏移 μ。
* **落地**：`bayes.py`
  * 用代理对每发历史实验求 `∂logY/∂δ` 的敏感度；
  * 以历史残差为似然，**MCMC** 推断 (涨落幅度 s, 系统偏移 μ)；
  * 对新设计做**蒙特卡洛传播**：抽 δ → 过代理 → 得到产额分布 → `P(Y > Y阈值)`。

### S5 稳健性设计 —— max E[Y] ≠ max P(点火)

* **原理**：平均产额最高的设计往往骑在点火悬崖边上，涨落一来就掉下去。
  真正该优化的是 `P(Y > 阈值)`，即**稳健性指标**。
* **落地**：`design.py`，三级漏斗：粗筛 → 线性化稳健性排序 → 蒙特卡洛精算。
  两个必须有的工程细节：
  * **可信域**：候选设计的集成离散度不得超过 held-out 仿真集上的水平。
    没有这一步，优化器会跑进训练数据稀疏的角落，找到代理"吹出来"的假最优解；
  * **闭环校验**：推荐设计必须丢回真实求解器复核（`S6b`），**代理不能自证**。

## 四之一、本机实跑结果（12000 次仿真 + 40 发"实验"，约 11 分钟）

| 环节 | 结果 |
|---|---|
| 代理 vs 仿真（held-out 仿真集） | log10 产额误差 **0.162 dex**（R²=0.963）；ρR 7.7%；bang time 2.8% |
| 加速比 | **≈210×**（仿真 2.77 ms/发 vs 代理 13 µs/发） |
| 迁移学习（25 发实验） | log10 产额盲测误差 **0.496 → 0.305 dex**；bang time 3.13%→0.98%；下散射比 26.2%→24.1% |
| 贝叶斯标定 | 涨落幅度 s = 1.21（真值 1.00），90%CI [0.92, 1.67] |
| **点火概率预测** | 上一代设计：预测 0.0%（真值 0.0%）<br>新一代设计：预测 **62.1%**（真值 **51.6%**），产额中位 2.45 MJ（真值 2.16） |
| 稳健 vs 传统设计 | 稳健设计真实点火概率 95.0% > 传统 94.5%，且产额 90% 区间更窄 |

**这些数字说明了什么**

* 迁移学习确实能"闭合仿真-实验鸿沟"，但**消不掉代理本身的误差**——
  产额盲测残差 0.3 dex ≈ 因子 2，这是 1.2×10⁴ 样本在 9 维空间 + 点火悬崖
  强非线性下的真实水平。LLNL 用 1.5×10⁵~10⁸ 样本正是为了压这一项。
* 点火概率的**排序和量级是对的**（0% / 62% vs 真值 0% / 52%），
  但略偏乐观 —— 说明残余误差还没被不确定度完全吸收。
* **自适应补样（悬崖带加密）把代理产额误差从 0.22 dex 压到 0.16 dex**，
  是投入产出比最高的一步。

## 五、已知的边界与限制（务必如实看待）

* **物理保真度**：`simulator.py` 是**降阶半解析模型**，用于验证方法论，
  不能当设计工具用。常数是标定出来的，不是第一性原理。
* **数据规模**：LLNL 是 10⁵~10⁸ 次仿真，本机是 10³~10⁴。
  维数灾难意味着代理在边角区域仍会外推 —— 这正是本项目保留
  "可信域过滤 + 闭环校验"的原因，跑完看 `S6b` 的对比就知道代理在哪些区域不可信。
* **涨落模型**：只推断了一个全局幅度 s + 4 个相对权重的工程先验。
  真实做法应推断完整的协方差矩阵，并且随实验积累不断更新。
* **未实现**（但架构上留了口子）：主动学习/自适应采样、多保真度融合、
  真正的 HPC 队列（Merlin）、PINN 形式的物理约束损失。

## 六、往上扩展的路线

| 想升级什么 | 改哪里 |
|---|---|
| 换真实辐射流体程序 | `workflow._run_one` → 调用 HYDRA / PLUTO / Castro / FLASH |

| 自适应采样 | `workflow.py` 加"worker 回写新任务"（Merlin 原生支持），按集成方差选下一批仿真点 |
| 接其它物理 | 这套**框架与 ICF 无关**：只要有"贵求解器 + 少量实验 + 多模态观测"，就可以套用 |
